# 选择用哪个飞书打开链接

从 **0.1.0-beta.6** 起，MultiApp 支持浏览器链接选择、默认飞书和粘贴链接打开。已有副本无需重建，也无需重新登录。

## 浏览器中「在飞书中打开」

1. 打开 MultiApp 左侧的 **链接打开方式**。
2. 点击 **启用链接选择**。如果 macOS 询问是否更改打开方式，确认使用 MultiApp。
3. 在浏览器点击 **在飞书中打开 / 立即打开**。浏览器可能询问是否打开 MultiApp，允许这次打开即可。
4. 在「用哪个飞书打开？」窗口，选择飞书原版或某个副本，再点 **打开链接**。列表显示自定义名称、数字图标和运行状态；没有运行的实例会被启动。

启用后 MultiApp 接收 `lark`、`feishu`、`feishu-open` 和 `x-feishu` 客户端链接，不改变默认浏览器、普通 HTTPS 链接或邮件的打开方式。MultiApp 退出后，系统可在收到客户端链接时重新启动它。

## 每次选择或设置默认飞书

- **每次选择飞书**是默认模式，适合工作、个人账号交替使用。
- 选择 **使用默认飞书**，再从列表指定一个实例，普通内容链接就直接交给该实例。
- 也可以在选择窗口勾选 **以后默认用这个飞书打开普通链接**。
- 原默认实例被移除、配置失效或暂时不可用时，会重新询问，不会悄悄改用另一个账号。
- 登录授权及无法识别的链接始终询问。授权回跳请选择最初发起登录的实例；SSO 完整流程尚未验证。

## 临时用另一个飞书打开

在 **链接打开方式 → 粘贴链接，选择飞书打开** 中粘贴链接，点击 **选择飞书打开…**。此入口始终询问，即使已经设置默认飞书，也可临时选择其他实例。无需先启用浏览器接管。

支持飞书客户端链接，以及 `feishu.cn`、`larkoffice.com` 和它们子域名下的 HTTPS 链接。文档链接会交给飞书文档入口；其他受支持网页交给客户端网页入口。短 AppLink 请先在浏览器打开，再使用页面的客户端打开按钮。

链接只在本机转交，不保存链接历史，不上传到 MultiApp 的服务器。选择窗口仅显示链接类别，不展示授权参数。是否有权访问内容仍由所选飞书账号决定；尚未登录的实例可能需要先完成登录。

## 恢复原来的打开方式

点击 **恢复原来的打开方式**。MultiApp 会恢复启用前记录的应用；原目标已不存在时，尝试恢复为当前选择的官方飞书。若某项已被其他软件更改，MultiApp 保留该项当前设置。卸载 MultiApp 前请先恢复。

如果飞书更新后浏览器又跳到其他实例，在本页点击 **刷新状态**，再按提示重新启用。浏览器有时会记住唤起应用的选择，需要在浏览器允许打开 MultiApp。

## 排队与操作保护

多条不同链接按顺序处理；选择窗口关闭时丢弃尚未处理的队列。队列仅驻留内存，最多 20 条。创建、重建、副本图标修改及管理器更新期间，待打开链接保留在选择窗口，操作结束后可以继续打开。

此功能不修改或重新签名飞书副本，不切换飞书内部账号，也不改变账号的文档权限。不同飞书版本、企业 SSO 和客户端内网页偏好可能影响最终打开行为。
